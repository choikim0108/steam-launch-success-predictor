# 팀 프로젝트 실행 계획

## 현재 계획 검토 결론

팀원이 작성한 일정과 단계 구성은 기본적인 성공 예측 모델 프로젝트로는 적절하다. 다만 이 프로젝트에서 "예측"이라는 표현을 유지하려면 한 가지를 반드시 보완해야 한다.

```text
현재 전체 리뷰 수/긍정률만 사용하면 현재 성과 분류에 가깝다.
출시 후 90일 성공 예측으로 설명하려면 리뷰별 timestamp를 수집해 7일/30일/90일 지표를 직접 만들어야 한다.
```

따라서 기존 계획은 유지하되, 데이터 수집과 라벨링 단계에 다음 기준을 추가한다.

```text
입력 X:
상점 정보 + 출시 7일 이내 리뷰 지표

정답 y:
출시 90일 리뷰 수와 긍정률 기반 success_90d

금지:
90일 리뷰 수, 90일 긍정률, 현재 전체 리뷰 수 같은 결과 변수를 모델 입력 X에 넣지 않는다.
```

## 최종 프로젝트 방향

```text
Steam 신작 게임의 출시 초기 데이터를 활용한 90일 성공 가능성 예측 및 출시 전략 분석
```

핵심 목표는 다음과 같다.

- Steam 상점 정보와 출시 초기 리뷰 데이터를 수집한다.
- 출시 후 90일 리뷰 수와 긍정률을 기준으로 성공 라벨을 만든다.
- 출시 전/초기 정보만으로 90일 성공 가능성을 예측한다.
- 성공/비성공 게임의 특징을 EDA와 모델 해석으로 설명한다.
- 시간이 남으면 유사 게임 비교, 리뷰 키워드, SteamSpy/웹진 관심도는 보조 분석으로 추가한다.

## 전체 일정

| 기간 | 단계 | 목표 | 주요 산출물 |
| --- | --- | --- | --- |
| ~6/4 (목) | 1단계 데이터 수집 | Steam 상점/검색, appdetails, Reviews API 수집 완료 | `data/raw/`, 수집 로그 |
| ~6/8 (월) | 2단계 전처리/라벨링 | 7일/30일/90일 리뷰 지표와 `success_90d` 생성 | `data/interim/`, `data/processed/` |
| ~6/8 (월) | 3단계 EDA 시각화 | 성공/비성공 게임의 분포와 특징 비교 | EDA 차트, 요약 표 |
| ~6/11 (목) | 4단계 모델링/평가 | 3가지 분류 모델 학습 및 성능 비교 | 모델 파일, 성능표, 변수 중요도 |
| 6/12 (금) ~ 6/15 (월) | 최종 취합 | PPT 제작, 발표 피드백, 제출물 검수 | 최종 PPT, 보고서, HTML 리포트 |

## 단계별 작업 계획

### 1단계: 데이터 수집

담당: 용우님

수집 대상:

- Steam 검색/상점 크롤링 데이터
- Steam appdetails API 데이터
- Steam Reviews API 데이터

필수 수집 항목:

```text
appid
게임명
출시일
가격
장르
태그/카테고리
지원 언어
지원 플랫폼
싱글/멀티 여부
컨트롤러 지원 여부
도전과제 지원 여부
review timestamp_created
review voted_up
review text
```

주의할 점:

```text
리뷰 요약의 현재 total_reviews만으로는 90일 성공 라벨을 만들 수 없다.
반드시 리뷰별 timestamp_created를 수집해 출시일 기준 7일/30일/90일 누적 리뷰 수와 긍정률을 계산해야 한다.
```

보조 수집 후보:

- SteamSpy owners 추정치
- 현재 동접자
- 웹진/YouTube 검색 언급량
- Metacritic/OpenCritic 점수

보조 수집은 핵심 모델이 안정화된 뒤 진행한다.

### 2단계: 데이터 분류 및 Target 정의

담당: 지훈님, 용우님

작업:

- 수집 데이터를 게임 단위 테이블로 병합한다.
- 출시일 기준 7일/30일/90일 리뷰 지표를 생성한다.
- 성공 라벨 `success_90d`를 만든다.
- 모델 입력 X와 정답 y를 분리한다.

기본 성공 기준:

```text
success_90d =
출시 후 90일 리뷰 수 >= 500
AND 출시 후 90일 긍정률 >= 80%
```

대안 기준:

```text
같은 장르/출시연도 내 90일 리뷰 수 상위 25~30%
AND 출시 후 90일 긍정률 >= 75~80%
```

모델 입력 가능:

```text
가격
장르
태그/카테고리
지원 언어 수
플랫폼 수
싱글/멀티 여부
컨트롤러 지원 여부
도전과제 지원 여부
출시 7일 리뷰 수
출시 7일 긍정률
출시 7일 리뷰 증가 속도
```

모델 입력 제외:

```text
출시 90일 리뷰 수
출시 90일 긍정률
현재 전체 리뷰 수
현재 긍정률
현재 판매량 추정치
현재 동접자
현재 Metacritic 점수
```

### 3단계: 데이터 시각화 및 EDA

담당: 도현님

시각화 항목:

- 성공/비성공 라벨 분포
- 가격대별 성공률
- 장르별 성공률
- 태그/카테고리별 성공률
- 지원 언어 수와 성공률
- 플랫폼 수와 성공률
- 출시 7일 리뷰 수와 90일 성공 여부 관계
- 출시 7일 긍정률과 90일 성공 여부 관계
- 7일 리뷰 수에서 90일 리뷰 수로 이어지는 변화

해석 기준:

```text
표본 수가 10개 미만인 장르/태그는 강한 결론을 내지 않는다.
장르별 비교는 최소 10개 이상, 가능하면 30개 이상일 때만 주요 인사이트로 사용한다.
```

### 4단계: 분류 모델링 및 평가

담당: 공동 작업

모델 후보:

- Logistic Regression
- Decision Tree
- Random Forest

평가 지표:

- Accuracy
- Precision
- Recall
- F1-score

권장 해석:

```text
성공/비성공 라벨 불균형이 있을 수 있으므로 Accuracy만 보지 않고 F1-score를 함께 본다.
Random Forest는 변수 중요도 해석에 활용한다.
Logistic Regression은 방향성과 설명 가능성 비교에 활용한다.
Decision Tree는 규칙 기반 설명 예시에 활용한다.
```

최종 산출물:

- 모델별 성능 비교표
- confusion matrix
- feature importance
- 최종 선택 모델
- 한계점 정리

## 보조 분석 범위

핵심 모델 이후 시간이 남으면 아래 항목을 추가한다.

### 유사 게임 추천

목적:

```text
내 게임과 비슷한 게임 10~30개를 찾아 성공작/실패작 평균 비교에 사용한다.
```

방법:

```text
장르, 태그, 가격, 언어 수, 플랫폼, 기능을 벡터화
KNN 또는 cosine similarity로 유사 게임 탐색
```

### 리뷰 키워드 분석

목적:

```text
유사 성공작과 실패작의 긍정/부정 리뷰에서 반복되는 키워드를 추출한다.
```

방법:

```text
긍정 리뷰와 부정 리뷰 분리
TF-IDF 또는 n-gram 빈도 분석
bug, optimization, repetitive 같은 키워드를 카테고리로 묶기
```

### SteamSpy/웹진 관심도

목적:

```text
판매량 추정치와 외부 매체 관심도를 현재 성과 비교 지표로 제공한다.
```

주의:

```text
SteamSpy와 웹진 관심도는 과거 시점 복원이 어렵기 때문에 90일 예측 모델의 핵심 입력이 아니라 보조 비교 지표로 둔다.
```

## 회의에서 확정해야 할 것

다음 항목만 확정하면 팀 전체 작업이 덜 흔들린다.

```text
1. 최종 주제를 "출시 초기 데이터 기반 90일 성공 예측"으로 표현할지
2. success_90d 기준을 절대 기준으로 둘지, 장르별 상대 기준도 함께 볼지
3. MVP 수집 규모를 300~500개로 할지, 1,000개 이상으로 도전할지
4. SteamSpy/웹진 관심도는 필수인지 보조인지
5. 최종 발표에 HTML 대시보드 시연 또는 캡처를 포함할지
```

## 리스크와 대응

| 리스크 | 영향 | 대응 |
| --- | --- | --- |
| 리뷰 timestamp 수집량이 부족함 | 90일 라벨 신뢰도 하락 | 게임 수를 줄이고 리뷰 타임라인 품질을 우선 |
| 출시일 파싱 오류 | 7/30/90일 계산 오류 | 날짜 파싱 실패 게임 제외 또는 수동 확인 |
| 특정 장르 표본 부족 | 장르별 결론 왜곡 | 최소 표본 수 기준 적용 |
| 성공 라벨 불균형 | 모델 성능 왜곡 | F1-score, confusion matrix 함께 확인 |
| SteamSpy/웹진 수집 불안정 | 보조 지표 누락 | 핵심 모델에서 제외하고 선택 분석 처리 |
| 발표 자료 과도한 범위 | 마감 리스크 | 필수/보조/선택 범위 분리 |

## 팀원에게 전달할 요약 문장

```text
전체 일정은 괜찮습니다. 다만 90일 성공 예측이라고 설명하려면 현재 리뷰 요약만 쓰면 안 되고, 리뷰별 timestamp를 수집해 출시 후 7일/30일/90일 지표를 직접 만들어야 합니다. 모델 입력에는 7일 이내 정보만 사용하고, 90일 리뷰 수와 긍정률은 success_90d 라벨 생성에만 사용하는 방향으로 정리하면 좋겠습니다.
```
