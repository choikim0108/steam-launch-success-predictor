# 개발자 경험과 사용자 경험 설계

## 프로젝트 정의

이 프로젝트는 Steam 신작 게임의 출시 초기 데이터를 활용해 출시 후 90일 성공 가능성을 예측하고, 현재 성과 지표와 유사 게임 리뷰 분석을 함께 제공해 게임 개발자가 출시 전략을 조정할 수 있도록 돕는 시스템이다.

핵심은 예측과 분석을 분리하는 것이다.

```text
예측:
출시 전/출시 7일 이내 데이터 -> 출시 90일 성공 여부

분석:
현재 판매량 추정치, 평론가 점수, 웹진 언급량, 동접자 -> 현재 성과 비교

피드백:
유사 게임의 긍정/부정 리뷰 키워드 -> 강화 요소와 위험 요소 제안
```

## 왜 시간 기준을 분리해야 하는가

성공 가능성 예측 모델은 예측 시점에 알 수 있는 데이터만 입력으로 사용해야 한다. 현재 전체 리뷰 수, 현재 판매량 추정치, 현재 동접자, 현재 Metacritic 점수처럼 이미 결과에 가까운 값은 모델 입력으로 넣으면 안 된다.

따라서 모델은 다음 구조를 기준으로 한다.

```text
X = 상점 정보 + 출시 7일 이내 리뷰 지표
y = 출시 90일 후 성공 여부
```

시간에 따른 변화를 안정적으로 계산할 수 있는 핵심 데이터는 Steam 리뷰다. Steam 리뷰에는 작성 시점, 긍정/부정 여부, 리뷰 텍스트가 포함되므로 출시일 기준 7일, 30일, 90일 지표를 만들 수 있다.

## 데이터 역할 구분

| 데이터 | 시간별 계산 가능성 | 예측 모델 입력 | 주요 용도 |
| --- | --- | --- | --- |
| Steam 상점 정보 | 과거 상태는 제한적 | 가능 | 가격, 장르, 태그, 언어, 플랫폼, 기능 feature |
| Steam 리뷰 timestamp | 가능 | 가능 | 7일/30일/90일 리뷰 지표 |
| Steam 리뷰 긍정/부정 | 가능 | 가능 | 초기 반응 feature, 90일 성공 라벨 |
| Steam 리뷰 텍스트 | 가능 | 제한적 | 유사 게임 리뷰 피드백 분석 |
| SteamSpy owners | 현재 스냅샷 중심 | 제한적 | 판매량 추정 성과 비교 |
| Metacritic/OpenCritic 점수 | 현재 스냅샷 중심 | 제한적 | 평론가 평가 비교 |
| 웹진/YouTube/블로그 언급량 | 현재 스냅샷 중심 | 제한적 | 외부 관심도 비교 |
| 현재 동접자 | 현재 순간값 | 제한적 | 현재 활성도 비교 |

## 개발자 경험

개발자 경험은 우리 팀이 데이터를 수집하고, 정제하고, 모델과 리포트를 만드는 흐름이다.

```text
[데이터 수집]
 Steam 검색 크롤링
 Steam appdetails API
 Steam Reviews API
 SteamSpy
 Steam Web API
 외부 웹/웹진 검색
        |
        v
[시간 기준 정제]
 출시일 기준 7일/30일/90일 리뷰 수 계산
 출시일 기준 7일/30일/90일 긍정률 계산
 상점 정보 feature화
 결측값 처리
        |
        v
[90일 성공 라벨 생성]
 success_90d
 review_success_score
 장르별 상대 기준 검토
        |
        v
[예측 모델 학습]
 Logistic Regression
 Random Forest
 필요 시 XGBoost 확장
        |
        v
[현재 성과 지표 추가]
 sales_proxy_score
 critic_score
 attention_score
 activity_score
        |
        v
[분석 모듈 생성]
 유사 게임 추천
 성공작/실패작 평균 비교
 리뷰 키워드 분석
 부족 요소 표시
        |
        v
[대시보드 출력]
 Markdown 문서
 CSV 산출물
 HTML 리포트
```

## 개발자 구현 단계

1. Steam 검색 페이지에서 appid 후보를 수집한다.
2. appid별 Steam appdetails API로 상점 정보를 수집한다.
3. Steam Reviews API로 리뷰 텍스트, 작성 시점, 긍정/부정 여부를 수집한다.
4. 출시일 기준으로 7일, 30일, 90일 리뷰 지표를 만든다.
5. `success_90d` 라벨을 생성한다.
6. 상점 정보와 출시 7일 리뷰 지표를 모델 입력으로 만든다.
7. 출시 90일 성공 여부를 예측하는 분류 모델을 학습한다.
8. SteamSpy, Metacritic/OpenCritic, 웹진/YouTube, 현재 동접자 지표를 현재 성과 비교용으로 추가한다.
9. KNN 또는 cosine similarity로 유사 게임을 찾는다.
10. 유사 성공작/실패작 평균과 내 게임 입력값을 비교한다.
11. 유사 게임 리뷰에서 긍정/부정 키워드를 추출한다.
12. 사용자에게 보여줄 HTML 대시보드를 생성한다.

## 데이터 규모와 현실 가능성

이 프로젝트는 "많이 수집할수록 좋다"가 아니라, 분석 목적별로 필요한 최소 표본 수가 다르다. 특히 장르별 비교, 유사 게임 추천, 리뷰 키워드 분석은 각각 필요한 데이터 양이 다르므로 기준을 분리해야 한다.

### 분석별 최소 표본 기준

| 분석 목적 | 최소 기준 | 권장 기준 | 비고 |
| --- | ---: | ---: | --- |
| 전체 모델 학습 | 유효 게임 300개 이상 | 유효 게임 800~1,500개 | 90일 지표가 있는 게임만 사용 |
| 장르별 성공률 비교 | 장르별 10개 이상 | 장르별 30개 이상 | 10개 미만 장르는 해석 제외 |
| 가격대/언어 수 비교 | 구간별 20개 이상 | 구간별 50개 이상 | 구간이 너무 많으면 합친다 |
| 유사 게임 추천 | 후보군 300개 이상 | 후보군 1,000개 이상 | 장르/태그 다양성이 중요 |
| 유사 성공작/실패작 평균 | 각 그룹 5개 이상 | 각 그룹 15개 이상 | 한쪽 그룹이 작으면 경고 표시 |
| 리뷰 키워드 분석 | 그룹별 리뷰 100개 이상 | 그룹별 리뷰 500개 이상 | 유사 게임 묶음 단위 기준 |
| 웹진 관심도 비교 | 게임당 검색 결과 0~10건 | 유사 게임군 100개 이상 | 절대 점수보다 상대 비교 중심 |

현재 수집 규모가 작을 때는 모델 결론보다 데이터 탐색과 UX 시연에 초점을 둔다. 최종 보고서에서는 표본 수가 작은 항목에 "해석 주의"를 붙인다.

### 수집 단계별 예상 시간

수집 시간은 네트워크 상태와 요청 간 sleep 설정에 따라 달라진다. 아래는 현실적인 범위 추정이다.

| 단계 | 요청 수 예시 | 예상 시간 | 현실성 |
| --- | ---: | ---: | --- |
| Steam 검색 페이지 appid 수집 | 10~50 페이지 | 1~5분 | 높음 |
| Steam appdetails 수집 | 게임당 1회 | 500개 기준 3~10분 | 높음 |
| Steam 리뷰 요약 수집 | 게임당 1회 | 500개 기준 3~10분 | 높음 |
| Steam 리뷰 타임라인 수집 | 게임당 여러 페이지 | 500개 기준 30분~2시간 | 중간 |
| SteamSpy owners 수집 | 게임당 1회 | 500개 기준 10~30분 | 중간 |
| 현재 동접자 수집 | 게임당 1회 | 500개 기준 5~15분 | 높음 |
| 웹진/YouTube 검색 | 게임당 여러 쿼리 | 100개 기준 20~60분 | 중간 |
| Metacritic/OpenCritic 직접 수집 | 게임명 매칭 필요 | 불안정 | 낮음~중간 |

MVP에서는 Steam 검색, appdetails, Reviews API, 일부 리뷰 텍스트, SteamSpy를 우선 구현한다. 웹진 검색은 모든 게임에 적용하지 않고 유사 게임 후보나 상위 관심 게임에만 제한한다.

### 90일 예측을 위한 현실적 수집 범위

90일 성공 예측을 하려면 출시 후 최소 90일이 지난 게임만 학습 데이터로 써야 한다.

```text
학습 데이터 포함:
출시일이 현재 기준 90일 이상 지난 게임

학습 데이터 제외:
coming soon
출시 후 90일이 지나지 않은 게임
리뷰 timestamp가 부족한 게임
앱 타입이 game이 아닌 항목
```

추천 수집 전략:

```text
1차 MVP:
최근 1~2년 내 출시작 300~500개
리뷰 요약 + 제한된 리뷰 타임라인

2차 모델 개선:
최근 3~5년 내 출시작 1,000~2,000개
게임당 최대 리뷰 500~1,000개까지 타임라인 수집

3차 확장:
장르별 균형 샘플링
SteamSpy owners와 웹진 관심도 일부 추가
```

### 리뷰 타임라인 수집 방식

90일 지표를 만들려면 리뷰 요약만으로는 부족하다. 리뷰별 `timestamp_created`와 `voted_up`을 수집해서 출시일 기준으로 누적 계산한다.

```text
release_date
review.timestamp_created
review.voted_up

days_since_release = review_date - release_date
```

생성 지표:

```text
reviews_7d
positive_rate_7d
reviews_30d
positive_rate_30d
reviews_90d
positive_rate_90d
review_velocity_7d
review_velocity_30d
```

게임별 모든 리뷰를 무제한으로 가져오면 시간이 오래 걸리므로, MVP에서는 게임당 최대 리뷰 수를 제한한다.

```text
MVP 제한:
게임당 최대 500개 리뷰

확장 제한:
게임당 최대 1,000~2,000개 리뷰

초대형 히트작:
90일 지표 계산에 필요한 구간까지만 수집하거나 샘플링
```

### 현실 가능성 판단

| 기능 | MVP 가능성 | 최종 보고서 가능성 | 판단 |
| --- | --- | --- | --- |
| 90일 리뷰 기반 성공 라벨 | 가능 | 가능 | 핵심 기능 |
| 출시 7일 -> 90일 성공 예측 | 일부 가능 | 가능 | 리뷰 타임라인 수집 필요 |
| 유사 게임 추천 | 가능 | 가능 | KNN/cosine similarity로 구현 가능 |
| 성공작/실패작 평균 비교 | 가능 | 가능 | 표본 수 기준 필요 |
| 리뷰 키워드 피드백 | 가능 | 가능 | 노이즈 제거와 그룹별 최소 리뷰 수 필요 |
| SteamSpy 판매량 proxy | 가능 | 가능 | 비공식 추정치임을 명시 |
| 웹진 관심도 지표 | 제한적 가능 | 보조 지표로 가능 | 전체 게임이 아니라 후보군 중심 |
| Metacritic/OpenCritic 직접 수집 | 불안정 | 선택 확장 | 핵심 기능에서 제외 권장 |

따라서 최종 구현 우선순위는 다음과 같다.

```text
1순위:
Steam 상점 정보 + 리뷰 타임라인 + success_90d + 예측 모델

2순위:
유사 게임 추천 + 성공작/실패작 평균 비교

3순위:
리뷰 키워드 피드백

4순위:
SteamSpy 판매량 proxy

5순위:
웹진 관심도 보조 지표

선택:
Metacritic/OpenCritic 직접 수집
```

## 예측 모델

예측 모델의 목적은 출시 초기 데이터로 90일 성공 가능성을 계산하는 것이다.

```text
입력 feature:
- 가격
- 장르/태그
- 지원 언어 수
- 플랫폼 수
- 싱글/멀티 여부
- 컨트롤러 지원 여부
- 도전과제 지원 여부
- 출시 7일 리뷰 수
- 출시 7일 긍정률
- 출시 7일 리뷰 증가 속도

정답 label:
- success_90d
```

`success_90d`는 기본적으로 다음처럼 정의한다.

```text
success_90d =
출시 90일 리뷰 수 >= 기준값
AND 출시 90일 긍정률 >= 기준값
```

장르별 규모 차이가 크면 같은 장르/출시연도 내 리뷰 수 상위 분위수와 긍정률 기준을 함께 검토한다.

## 현재 성과 분석

SteamSpy, Metacritic/OpenCritic, 웹진 언급량, 현재 동접자는 예측 모델의 핵심 입력이 아니라 현재 성과 비교 지표로 둔다.

```text
sales_proxy_score:
SteamSpy owners 추정치, 플레이타임

critic_score:
Metacritic/OpenCritic 점수

attention_score:
YouTube, 웹진, 블로그, 커뮤니티 언급량

activity_score:
현재 동접자, 현재 플레이 유지 지표
```

이 지표들은 대시보드에서 다음 질문에 답하기 위해 사용한다.

```text
판매량 추정 기준으로 잘 된 게임인가?
평론가 평가 기준으로 좋은 게임인가?
웹진/유튜브에서 관심을 받은 게임인가?
현재도 플레이어가 남아 있는 게임인가?
```

## 웹진 관심도 조사 설계

웹진 데이터는 "게임의 품질을 직접 평가하는 정답"이 아니라, 외부 매체에서 얼마나 다뤄졌는지를 보는 관심도와 신뢰도 보조 지표다. 따라서 예측 모델의 핵심 입력으로 사용하기보다, 현재 성과 비교와 사용자 화면의 시장 반응 설명에 사용한다.

### 조사 대상

웹진은 처음부터 모든 사이트를 무작위로 긁지 않고, 도메인을 고정한다. 그래야 재현 가능한 지표가 된다.

```text
글로벌 게임 웹진:
- ign.com
- gamespot.com
- pcgamer.com
- rockpapershotgun.com
- polygon.com
- eurogamer.net

영상/커뮤니티 보조:
- youtube.com
- reddit.com

블로그/롱폼 보조:
- medium.com
- substack.com
```

초기 구현에서는 글로벌 웹진 4~6개만 사용하고, YouTube/Reddit/블로그는 별도 보조 지표로 둔다.

### 수집 방법

웹진 사이트마다 HTML 구조가 다르므로 각 사이트를 직접 크롤링하는 방식은 유지보수 부담이 크다. MVP에서는 검색 API 또는 검색 결과 페이지를 통해 "게임명 + site:도메인" 쿼리로 후보 문서를 수집한다.

예시 쿼리:

```text
"Hades II" game site:ign.com
"Hades II" review site:pcgamer.com
"Hades II" preview site:gamespot.com
"Hades II" gameplay site:youtube.com
```

수집 컬럼:

```text
appid
game_name
source_domain
query_type        # review, preview, news, guide, video
result_rank       # 검색 결과 순위
title
url
snippet
published_date    # 가져올 수 있을 때만
collected_at
```

공식 검색 API를 쓸 수 있으면 Google Programmable Search JSON API처럼 `q`, `cx`, `siteSearch` 또는 `site:` 쿼리를 사용하는 방식이 가장 안정적이다. API 키 없이 구현해야 하면 DuckDuckGo/Bing HTML 검색을 보조 방식으로 쓰되, 결과 수는 불안정한 proxy라고 명시한다.

### 필터링 규칙

검색 결과를 그대로 세면 노이즈가 많으므로 최소한의 필터링을 한다.

```text
포함:
- 제목 또는 snippet에 게임명이 포함됨
- 도메인이 사전에 정한 웹진 목록에 포함됨
- review, preview, impressions, hands-on, guide, news 중 하나와 관련 있음

제외:
- Steam 상점 페이지
- 판매 페이지
- 중복 URL
- 게임명과 무관한 동명이인/다른 상품
- 너무 짧은 snippet 또는 내용 없는 인덱스 페이지
```

### 점수화 방식

웹진 점수는 기사 수를 그대로 쓰지 않고, 도메인 신뢰도와 검색 순위를 반영한 가중 점수로 만든다.

```text
article_weight =
domain_weight * query_type_weight * rank_weight

domain_weight:
주요 웹진 1.0
일반 블로그 0.5
커뮤니티/영상 0.4

query_type_weight:
review 1.0
preview/hands-on 0.8
news 0.6
guide 0.4

rank_weight:
1위 1.0
2~3위 0.8
4~10위 0.5
```

최종 지표:

```text
webzine_mention_count
webzine_weighted_score
review_article_count
preview_article_count
top_domains
top_article_titles
```

점수 등급:

```text
높음: 유사 게임 상위 25%
보통: 유사 게임 중간 50%
낮음: 유사 게임 하위 25%
없음: 수집 결과 없음
```

### 사용자에게 보여주는 방식

사용자에게는 단순히 "웹진 점수 12점"만 보여주면 안 된다. 어떤 매체가 어떤 맥락으로 다뤘는지 보여줘야 한다.

화면 구성:

```text
외부 매체 관심도: 낮음/보통/높음

근거:
- IGN review 기사 1건
- PC Gamer preview 기사 1건
- YouTube gameplay 검색 결과 6건

유사 성공작 평균:
- 웹진 가중 점수 18.4
- review 기사 평균 2.1건

내 게임:
- 웹진 가중 점수 4.2
- review 기사 0건

해석:
유사 성공작 대비 웹진 노출이 낮다. 출시 전 데모, 프레스킷, 트레일러 배포를 통해 preview/review 기사 후보를 늘리는 전략을 검토한다.
```

### 주의점

웹진 데이터는 다음 한계가 있다.

```text
과거 시점의 웹진 노출량을 안정적으로 복원하기 어렵다.
검색 결과는 검색엔진 상태에 따라 바뀔 수 있다.
기사 수가 많다고 게임 품질이 높다는 뜻은 아니다.
대형 퍼블리셔 게임은 웹진 노출이 구조적으로 많을 수 있다.
```

따라서 웹진 지표는 "90일 성공 예측의 핵심 feature"가 아니라 "현재 시장 관심도와 마케팅 노출 수준을 설명하는 보조 지표"로 사용한다.

## 유사 게임 추천

유사 게임 추천은 성공 예측 모델과 별도 모듈로 둔다.

```text
입력:
장르, 태그, 가격, 언어 수, 플랫폼, 기능, 초기 리뷰 지표

방법:
StandardScaler + OneHotEncoder
KNN 또는 cosine similarity

출력:
내 게임과 비슷한 게임 10~30개
```

유사 게임은 다음 분석의 기준이 된다.

```text
유사 성공작 평균
유사 실패작 평균
리뷰 키워드 분석
부족 요소 표시
```

## 리뷰 기반 피드백

리뷰 기반 피드백은 확정적인 조언이 아니라 유사 게임 리뷰에서 반복적으로 나온 패턴을 보여주는 기능이다.

```text
유사 성공작 긍정 리뷰:
강점 후보

유사 성공작 부정 리뷰:
성공작에서도 주의해야 하는 문제

유사 실패작 부정 리뷰:
실패 위험 요소

유사 실패작 긍정 리뷰:
성과가 낮아도 유저가 좋아한 요소
```

초기 구현은 TF-IDF, n-gram, 빈도 비교를 사용한다. 추출된 단어는 사람이 이해하기 쉬운 카테고리로 묶는다.

```text
bug, crash -> 안정성/버그
optimization, fps, stutter -> 최적화
boring, repetitive, grind -> 반복성/콘텐츠
balance, unfair -> 밸런스
controller, input, clunky -> 조작감
tutorial, confusing -> 진입장벽
```

## 사용자 경험

사용자는 Steam 출시를 준비하거나 출시 초기 반응을 확인하는 게임 개발자다. 사용자는 단순히 성공 확률을 보고 싶은 것이 아니라, 무엇을 먼저 강화해야 하는지 알고 싶어 한다.

```text
[시장 트렌드 보기]
        |
        v
[내 게임 정보 입력]
        |
        v
[비슷한 게임 확인]
        |
        v
[90일 성공 가능성 확인]
        |
        v
[현재 성과 지표 기준 비교]
        |
        v
[리뷰 피드백 확인]
        |
        v
[강화 우선순위 결정]
```

## 사용자 화면 흐름

### 1. 시장 트렌드 보기

사용자는 먼저 요즘 Steam에서 어떤 장르와 태그가 잘 반응하는지 확인한다.

표시 항목:

- 최근 장르별 성공 비율
- 리뷰 증가가 빠른 게임
- 판매량 추정치가 높은 게임
- Metacritic 점수가 높은 게임
- 평점 대비 판매량 추정치가 높은 게임
- 웹진/YouTube 언급량이 많은 게임

### 2. 내 게임 정보 입력

사용자는 자신의 게임 정보를 입력한다.

- 장르
- 태그
- 가격
- 지원 언어 수
- 플랫폼
- 싱글/멀티 여부
- 컨트롤러 지원 여부
- 도전과제 지원 여부
- 출시 초기 리뷰 수와 긍정률이 있으면 입력

### 3. 비슷한 게임 확인

입력된 정보와 유사한 Steam 게임 10~30개를 보여준다.

각 게임에는 다음 정보를 함께 보여준다.

- 리뷰 수
- 긍정률
- 판매량 추정치
- Metacritic/OpenCritic 점수
- 웹진/YouTube 언급량
- 현재 동접자

### 4. 90일 성공 가능성 확인

예측 모델이 출시 90일 성공 가능성을 보여준다.

예시:

```text
90일 성공 가능성: 62%
기준: 90일 리뷰 수 + 90일 긍정률
같은 장르 평균 대비: 보통
```

### 5. 성공작/실패작 비교

유사 게임을 성공작과 실패작으로 나누고 평균을 비교한다.

비교 항목:

- 가격
- 지원 언어 수
- 컨트롤러 지원률
- 멀티플레이 지원률
- 리뷰 수
- 긍정률
- 판매량 추정치
- Metacritic/OpenCritic 점수
- 웹진/YouTube 언급량
- 현재 동접자

### 6. 리뷰 피드백 확인

유사 게임의 리뷰 텍스트에서 반복적으로 등장하는 긍정/부정 키워드를 보여준다.

예시:

```text
유사 성공작 긍정 키워드:
combat, story, replayability, art style

유사 실패작 부정 키워드:
bug, optimization, boring, repetitive, balance
```

### 7. 강화 우선순위 제안

마지막으로 개발자가 먼저 강화할 요소를 정리한다.

예시:

```text
1. 지원 언어 확대
   유사 성공작 평균은 12개, 현재 입력값은 4개

2. 컨트롤러 지원 검토
   유사 성공작의 78%가 컨트롤러 지원

3. 가격대 재검토
   현재 가격이 유사 성공작 중앙값보다 높음

4. 최적화/반복성 점검
   유사 실패작 부정 리뷰에서 optimization, repetitive 키워드 반복
```

## 최종 사용자 가치

사용자는 다음 흐름으로 판단할 수 있다.

```text
요즘 트렌드를 확인한다.
내 게임이 어떤 시장에 속하는지 본다.
비슷한 게임의 성공/실패 패턴을 비교한다.
90일 성공 가능성을 확인한다.
유사 게임 리뷰에서 자주 나온 위험 요소를 본다.

```
