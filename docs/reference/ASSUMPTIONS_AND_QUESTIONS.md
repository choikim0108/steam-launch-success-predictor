# 가정 및 확인 질문

## 현재 확정 가정

- 프로젝트의 핵심 예측 문제는 "출시 초기 데이터로 출시 후 90일 성공 여부를 예측할 수 있는가?"이다.
- 시간에 따른 변화를 안정적으로 만들 수 있는 핵심 데이터는 Steam 리뷰 timestamp다.
- 현재 전체 리뷰 수와 현재 긍정률은 예측 입력이 아니라 현재 성과 참고 지표다.
- SteamSpy, 웹진 관심도, 현재 동접자, Metacritic/OpenCritic은 현재 스냅샷 성격이 강하므로 보조 분석으로 둔다.
- 초기 현재 누적 리뷰 기준 모델 결과는 `legacy/current_snapshot/`에 보존하고 최종 결과로 사용하지 않는다.

## 성공 라벨 후보

기본 절대 기준:

```text
success_90d =
reviews_90d >= 500
AND positive_rate_90d >= 0.80
```

장르 보정 기준:

```text
success_90d =
같은 장르/출시연도 내 reviews_90d 상위 25~30%
AND positive_rate_90d >= 0.75~0.80
```

두 기준을 모두 실험하고, 최종 발표에서는 해석이 더 안정적인 기준을 선택한다.

## 수집 가정

- 출시 후 90일이 지나지 않은 게임은 학습 데이터에서 제외한다.
- `type != game` 또는 `coming_soon == true` 항목은 제외한다.
- 출시일 파싱이 불가능한 게임은 90일 지표 계산에서 제외하거나 별도 검토한다.
- 리뷰가 극단적으로 많은 게임은 게임당 최대 리뷰 수를 제한한다.
- 장르별 표본 수가 10개 미만이면 강한 결론을 내지 않는다.

## 교수님 또는 팀 내 확인 질문

1. Steam 상점 HTML 크롤링과 Steam Reviews API를 서로 다른 데이터 source로 인정할 수 있는지
2. 성공 기준을 절대 기준으로 둘지, 장르별 상대 기준을 함께 사용할지
3. 출시 7일 리뷰 지표를 입력 feature로 사용하는 "출시 초기 예측" 표현이 과제 의도에 맞는지
4. SteamSpy owners 추정치를 판매량 proxy로 보조 분석에 사용하는 것이 적절한지
5. 웹진 관심도는 전체 게임 대상이 아니라 유사 게임 후보군 중심으로 수집해도 되는지
6. 최종 제출 시 원천 HTML/JSON 파일까지 포함해야 하는지, 수집 코드와 요약 CSV만 제출해도 되는지
7. 모델 3개 비교 외에 클러스터링/추천/리뷰 키워드 분석을 보조 분석으로 넣는 것이 평가에 도움이 되는지

## 현재 리스크

| 리스크 | 대응 |
| --- | --- |
| 리뷰 타임라인 수집 시간이 길어짐 | MVP는 300~500개 게임, 게임당 리뷰 500개 제한 |
| 출시일 파싱 실패 | 파싱 실패 목록을 별도 CSV로 저장하고 제외 기준 명시 |
| success_90d 클래스 불균형 | 기준값 조정 또는 장르별 상대 기준 실험 |
| 웹진/SteamSpy 수집 불안정 | 핵심 모델에서 제외하고 보조 분석으로 처리 |
| 기존 레거시 산출물과 혼동 | `legacy/current_snapshot/`로 분리하고 새 산출물은 `_90d` suffix 사용 |
